# Build notes

## What I'd flag about the original file

- **Two entire `<style>` blocks, only the second matters.** Lines 12–633 are
  a full dark "V1" layout+palette; lines 634–823 are a "V2" palette-only
  override that wins the cascade outright. Net result = V1's layout with
  V2's colors. If I hadn't read every line, I'd have shipped the dead V1
  palette as the real one. Full breakdown in `docs/PROTOTYPE-ANALYSIS.md`.
- **Shop has 8 cards for 4 products** — two different image techniques
  (CSS background-image spans vs. hand-drawn inline SVGs) applied to the
  identical 4 products, never reconciled. Reviews' marquee legitimately
  duplicates 5 cards to 10 for the seamless scroll loop — that one's
  intentional and I kept the technique, just generated by a real loop.
- **Add-to-cart, the mobile nav drawer, and email signup are all
  non-functional** — no form, no handler, `onsubmit="return false"`.
  Combos' "Shop bundle" copy ("opens the bundle picker with these
  products already added") describes a picker interaction that doesn't
  exist anywhere in the file's JS.
- **The reviews marquee has no reliable keyboard pause.** It pauses on
  `:hover`/`:focus-within`, but no element inside a review card is
  focusable — a keyboard-only visitor has no way to stop it. Likely a
  WCAG 2.2.2 issue.
- Orphaned PDP CSS (`.crumb`, `.gal-main`, `.vopt`, etc., ~40 lines) for a
  product detail page that isn't in this file at all. Didn't port it.

## What I changed, and why

- **Combos and Bundles are real Shopify products**, not Liquid-side
  arithmetic. Their price/compare-at price/savings come straight from
  the platform. Combos get a `custom.included_products` metafield
  (component products) that drives both the icon stack and a generated
  "Includes: A, B & C" sentence — replacing hand-written prose per card.
  Bundles get `custom.bundle_product_count` + `custom.bundle_perks` for
  the per-unit price math and bullet list. Full schema in
  `docs/METAFIELDS.md`.
- **Reviews are a metaobject**, since Shopify has no native review
  object and this is a fresh dev store with no real reviews to pull from
  an app yet. Documented as a stand-in for a real reviews app in
  METAFIELDS.md — swap the block type when one's installed.
- **Add-to-cart is now real**: wraps Dawn's existing `<product-form>`
  custom element and AJAX cart flow (`assets/product-form.js`,
  cart-notification/cart-drawer) instead of building a parallel system.
- **Scroll-reveal-on-load reuses Dawn's own `scroll-trigger` /
  `animate--slide-in` system** (already respects reduced motion, the
  theme editor's design-mode bypass, and the merchant's Animations theme
  setting) instead of porting the prototype's bespoke IntersectionObserver
  — no reason to ship two implementations of the same idea.
- **Reviews marquee gets a real pause/play button** (`purelane-reviews.js`)
  since the prototype's hover/focus-only pause had no focusable target.
- **Shop grid gets a 3-up tablet breakpoint** the prototype was missing
  (it jumped straight from 2 columns to 4 with nothing between ~760–860px),
  and card titles clamp to 2 lines so a very long title can't blow out
  row height — this is exactly what the seed data's long-title product
  tests.
- **Colors are theme settings** (Theme settings → Purelane brand colors),
  not hardcoded hex, defaulting to the approved palette. Fonts stay on
  Dawn's own font picker rather than a hardcoded Google Fonts `<link>`.
- **A second, independent review pass** against this brief's own grading
  bar (theme-editor safety, accessibility, reduced motion, Core Web
  Vitals, merchant editability, correctness) caught real issues after
  the sections "worked": Bundles had no accessible name for a tier at
  all (title existed only as `alt` text inside an `aria-hidden`
  wrapper); Combos/Bundles CTAs all read "Shop bundle"/"Build this box"
  verbatim with nothing to disambiguate them out of visual context;
  several product/review titles rendered unescaped where Dawn's own
  snippets consistently escape them; a `{%- endif -%}` was eating the
  space between the generated "Includes:" sentence and the product
  description; `product-form.js` was loading once per card instead of
  once per section; the shared design-token CSS was loading sitewide
  instead of scoped to the 5 sections that use it. All fixed — see the
  git history for the actual diffs.
- **Cut, deliberately, for scope**: the full-page "scenes" water/parallax
  cinematic background, the ticker, the right-side scroll-progress rail,
  and the "why it works" product rotator. All bonus-scope per the brief;
  none of the 5 required sections depend on them, and the water
  cinematics in particular (huge inline SVGs, a `requestAnimationFrame`
  loop, mix-blend-mode layers) are a real Core Web Vitals risk for the
  return they give. The Hero and Reviews sections sit on a plain
  brand-color background instead.

## What I'd do with more time

- Wire a real reviews app (Judge.me/Loox/etc.) instead of the metaobject
  stand-in, and swap `custom.rating_average`/`rating_count` on Shop cards
  for whatever metafields that app writes.
- Build the actual "bundle picker" the prototype's copy implies —
  probably a small custom-element modal that lets a shopper pick N
  products into a bundle line-item property, rather than linking straight
  to the tier product.
- Automated visual regression (Percy/Playwright screenshots) at the
  breakpoints the CSS actually keys off — I verified data correctness
  and zero Liquid errors via the rendered HTML, but pixel-level visual
  diffing against the prototype needs a real browser session I couldn't
  get stable in this sandboxed environment (see `scripts/README.md`).
- A tablet-specific pass on the Combos scroll rail — it's usable but the
  scroll-snap card width (302px) wasn't re-tuned for the 3-up tablet
  range the way the Shop grid was.
